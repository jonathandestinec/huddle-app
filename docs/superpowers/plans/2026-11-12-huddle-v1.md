# Huddle v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Huddle v1 — organisations create events, attach RSVP / Number Picker / Extra Content functions gated free, paid (Paystack split) or by access code, and attendees unlock them from their phones with only name + email.

**Architecture:** One Next.js App Router app on Vercel. Postgres on Neon via Drizzle. Every external dependency sits behind a small module (`lib/auth`, `lib/storage`, `lib/realtime`, `lib/paystack`, `lib/email`). Functions are self-contained modules registered in `src/functions/registry.ts`; all access decisions go through `lib/gating`, and all paid access is granted only by `lib/payments/settle.ts`.

**Tech Stack:** Next.js 15, React 19, TypeScript (strict), Tailwind CSS v4, Drizzle ORM + `@neondatabase/serverless` (Pool driver, for transactions), Better Auth (magic link + Google), Zod, Resend + React Email, S3-compatible storage via `@aws-sdk/client-s3` + `@aws-sdk/s3-request-presigner`, bcryptjs, Motion (`motion/react`), Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-11-huddle-v1-design.md`

### Decisions taken from the spec's fallback column (deliberate)

- **Auth = Better Auth directly on the Neon DB.** Neon Auth is built on Better Auth; using it directly gives a stable, documented API with the same behaviour, and avoids a newer-product risk inside an 8-day window. Wrapped in `lib/auth` as the spec requires.
- **Realtime = 3-second polling first**, behind `lib/realtime`. Upgrading to Neon realtime is an optional post-launch task; no feature code changes.
- **Storage = S3-compatible API** (Neon storage buckets expose presigned URLs). `lib/storage` reads `S3_ENDPOINT` etc., so Vercel Blob/R2 is a config swap.

## Global Constraints

- All money is integer **kobo**. Huddle fee = `ceil(amount_kobo × fee_bps / 10000)`; default `fee_bps = 500` (5%).
- Paystack checkout: `subaccount` = org code, `transaction_charge` = Huddle fee in kobo, `bearer: "subaccount"`.
- Access is granted **only** by a verified webhook (`x-paystack-signature`, HMAC-SHA512 of raw body with `PAYSTACK_SECRET_KEY`) or server-side `GET /transaction/verify/:reference` — never by client redirect alone.
- Number holds last **10 minutes**; sweep runs every **5 minutes** (Vercel Cron).
- Access-code attempts: **5 per 10 minutes per function per IP**; generic error copy "That code didn't work".
- Signed file URLs expire after **1 hour**; uploads ≤ **500 MB**; allowed: pdf, mp3, m4a, mp4, mov, jpg, png.
- Number picker range: `max − min ≤ 9,999`; one number per attendee per event; one function of each type per event.
- Minimum paid price: **₦100 (10,000 kobo)**.
- Default timezone for event times entered by organisers: **Africa/Lagos**.
- Brand tokens: `--huddle-yellow #FFE76C`, `--ink #1A1A1A`, `--paper #FAFAF8`, `--surface #FFFFFF`, `--slate #64748B`. Headlines Instrument Serif (italic for expressive moments), body/UI Urbanist.
- Copy follows the brand voice ("Decide who gets in, and how.", "Pick what your event needs. Attach it. Done.", "Create your organisation — it takes 2 minutes."). Respect `prefers-reduced-motion`.
- Paystack **test** keys until Task 17 passes.

## Review Focus

1. **Inline attendee identify with an email that already has an account** → must NOT create a session; send a magic link instead ("Welcome back — check your email"). Otherwise anyone could type a churchgoer's email and see their purchases. Pinned in Task 3.
2. **Same attendee double-taps two numbers / two tabs** → second claim rejected with "You already hold #N". Pinned in Task 12.
3. **Organiser types a price like "2,000" or "1500.50"** → parsed exactly to kobo (200000 / 150050); below ₦100 rejected. Pinned in Task 8.
4. **Organiser edits or removes a function people have already paid for** → gate type cannot change and the function cannot be removed once any entitlement exists; price may change for future buyers only. Pinned in Task 8.
5. **Org slug that collides with an app route** (`dashboard`, `me`, `api`, `login`…) → rejected as reserved. Event times typed in Lagos are stored as the correct UTC instant. Pinned in Tasks 5 and 7.

### Task 10: Paid unlocks and settlement

**Files:**
- Create: `src/lib/paystack/signature.ts`, `src/lib/payments/start.ts`, `src/lib/payments/settle.ts`, `src/app/api/paystack/webhook/route.ts`, `src/app/[org]/[event]/paid/page.tsx`
- Test: `tests/unit/signature.test.ts`, `tests/integration/settle.test.ts`

**Interfaces:**
- Produces: `verifyPaystackSignature(rawBody: string, signature: string | null): boolean` (HMAC-SHA512, `timingSafeEqual`).
- Produces: `startPaidUnlock(userId, functionId, metadata: Record<string, unknown>): Promise<{ authorizationUrl: string; reference: string }>` — creates `pending` payment (reference `hud_<cuid>`), amount = function price, fee = `huddleFeeKobo`, callback `${APP_URL}/{org}/{event}/paid?ref=…`.
